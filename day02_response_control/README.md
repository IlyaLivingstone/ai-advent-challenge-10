# День 2. Управление форматом ответа LLM

Spring Boot-сервис для сравнения одного и того же запроса в разных режимах контроля ответа: без ограничений, с явным форматом, `max_tokens`, `stop sequence` и строгой JSON-схемой.

## Стек

- Java 21;
- Spring Boot 4.1.2;
- Maven 3.9+.

## Проверка DeepSeek API

- `max_tokens` учитывает reasoning-токены: при слишком низком лимите модель может вернуть пустой `content` с `finish_reason=length`.
- `stop` принимается API, но на компактном JSON может не сработать ожидаемым образом.
- `response_format={"type":"json_object"}` поддерживается.
- `response_format={"type":"json_schema"}` пока отклоняется API, поэтому строгая схема будет проверяться локально.
- Для обычных ответов нужен запас `max_tokens` (по умолчанию 1500).

## Эксперимент

Один и тот же вопрос: «Проанализируй идею мобильного приложения для учёта личных финансов. Верни название, целевую аудиторию, три ключевые функции и основной риск».

| Вариант | Управление |
| --- | --- |
| `baseline` | без ограничений |
| `explicit_format` | JSON-формат явно описан в промпте |
| `max_tokens` | JSON-формат + лимит 300 токенов |
| `stop_sequence` | JSON-формат + `stop = "\\n\\n"` |
| `strict_schema` | JSON Schema в промпте, JSON mode API и локальная валидация |

Для каждого запуска сохраняются `finish_reason`, токены, задержка, сырой ответ, результат прямого и нормализованного JSON-парсинга, ошибки JSON Schema и итоговые выводы.

Пример одного живого прогона:

- `baseline` — текст без JSON;
- `explicit_format` — валидный JSON по схеме;
- `max_tokens` — `finish_reason=length`, ответа в `content` нет;
- `stop_sequence` — валидный JSON, `stop` на компактном ответе не сработал;
- `strict_schema` — валидный JSON по схеме.

Результат зависит от формулировки и reasoning-токенов, поэтому сравнение выполняется на нескольких повторах.

## REST API

- `GET /api/experiments/meta` — запрос по умолчанию и описание вариантов;
- `POST /api/experiments` с телом `{"repeats":3,"prompt":"свой запрос"}` — запуск асинхронного эксперимента, ответ `202 Accepted`;
- `POST /api/experiments/preview` с телом `{"prompt":"свой запрос"}` — итоговые запросы для всех уровней контроля;
- `GET /api/experiments/{id}` — статус и результаты;
- `GET /api/health` — health-check.

Web-интерфейс доступен по адресу `http://localhost:8080/`: запрос можно отредактировать, а по клику на уровень контроля открывается точный итоговый промпт, который уйдёт в модель.

## День 3. Разные способы рассуждения

Страница `/day3/` сравнивает четыре способа промптинга:

- прямой ответ;
- «решай пошагово»;
- сначала сгенерировать промпт, затем решить задачу;
- группа экспертов: аналитик, инженер, критик.

Каждый способ выполняется в двух режимах:

- **low** — `thinking: disabled`, без reasoning-токенов;
- **high** — `thinking: enabled`, `reasoning_effort: max`.

Набор: 7 задач с известными ответами. Итоговый ответ извлекается из строки `FINAL:` и проверяется детерминированно.

API:

- `GET /api/reasoning/meta` — задачи, способы и режимы;
- `POST /api/reasoning/experiments` — запуск полного эксперимента;
- `GET /api/reasoning/experiments/{id}` — статус и отчёт.

Полный эксперимент: 56 решений + 14 запросов на генерацию meta-промптов.

### Задачи

Очередь с ограничениями, двоичные строки без трёх единиц подряд, пути с препятствиями, решения уравнения с ограничениями, раскраски графа, рекуррентная последовательность по модулю и вероятность без возвращения.

### Результаты полного прогона

| Способ | Low | High | Токены Low | Токены High | Время Low | Время High |
|---|---:|---:|---:|---:|---:|---:|
| Прямой ответ | 7/7 | 7/7 | 12 528 | 27 290 | 62,7 с | 148,5 с |
| Решай пошагово | 7/7 | 7/7 | 14 216 | 40 988 | 65,9 с | 210,3 с |
| Сначала промпт | 5/7 | 4/7 | 26 990 | 92 646 | 109,9 с | 545,0 с |
| Группа экспертов | 6/7 | 7/7 | 12 304 | 35 718 | 53,3 с | 188,0 с |

Итого: **Low — 25/28, High — 25/28**. Расход токенов вырос с 66 038 до 196 642, время — с 292 до 1 092 секунд (полный прогон занял 1 384 секунды).

Что видно:

- прямой ответ и пошаговый способ решают 7/7 в обоих режимах — ceiling effect;
- группа экспертов улучшилась с 6/7 до 7/7, но это единственное изменение в пользу high;
- meta-prompt деградировал с 5/7 до 4/7;
- одна low-ошибка meta-prompt — формат `последний — D`: ответ верный, но evaluator ждёт короткий `FINAL`;
- high-ответы meta-prompt дважды упёрлись в `max_tokens=16000` (binary и paths), а на colorings API вернул ошибку извлечения JSON;
- у expert-panel low один реальный неверный ответ на binary (90218 вместо 111659).

Главный вывод: на этом наборе **дополнительные приёмы промптинга не дают устойчивого прироста точности**, а при включённом reasoning резко растут токены и время. Meta-prompt — самый дорогой и самый хрупкий способ.

Полный отчёт с ответами и токенами: [`reports/day3-full-run.json`](reports/day3-full-run.json).

## Запуск

```bash
export DEEPSEEK_API_KEY="ваш_api_key"
mvn spring-boot:run
```

Проверка:

```bash
curl http://localhost:8080/api/health
```

Тесты:

```bash
mvn test
```

Живые тесты клиента и полного эксперимента запускаются отдельно:

```bash
DEEPSEEK_LIVE_TEST=true mvn -Dtest=DeepSeekClientLiveTest,ExperimentServiceLiveTest test
```
