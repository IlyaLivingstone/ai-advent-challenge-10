# День 3. Разные способы рассуждения

Самостоятельный Spring Boot-сервис для сравнения четырёх способов промптинга при двух настройках reasoning. Не зависит от `day02_response_control`, общий код LLM-клиента продублирован внутри модуля.

## Стек

- Java 21;
- Spring Boot 4.1.2;
- Maven 3.9+.

## Способы

- `direct` — прямой ответ без дополнительных инструкций;
- `step_by_step` — «решай пошагово»;
- `meta_prompt` — сначала модель генерирует промпт, затем решает по нему;
- `expert_panel` — аналитик, инженер и критик, затем общий итог.

Все ответы заканчиваются строкой `FINAL: <ответ>` и проверяются детерминированно.

## Режимы

- **low** — `thinking: disabled`, reasoning-токенов нет;
- **high** — `thinking: enabled`, `reasoning_effort: max`.

`max_tokens` для решения и генерации промпта — 16 000.

## Задачи

7 задач с известными ответами:

- очередь с ограничениями;
- двоичные строки без трёх единиц подряд;
- пути с препятствиями;
- решения уравнения с ограничениями;
- раскраски графа;
- рекуррентная последовательность по модулю;
- вероятность без возвращения.

## API

- `GET /api/reasoning/meta` — задачи, способы, режимы;
- `POST /api/reasoning/experiments` — запуск полного эксперимента;
- `GET /api/reasoning/experiments/{id}` — статус и отчёт;
- `GET /api/health` — health-check.

## Запуск

```bash
export DEEPSEEK_API_KEY="ваш_api_key"
mvn spring-boot:run
```

Сервис работает на `http://localhost:8081/`, интерфейс — на `/` и `/day3/`.

Тесты:

```bash
mvn test
```

Вывод: на этом наборе дополнительные приёмы промптинга не дают устойчивого прироста точности. High reasoning резко увеличивает стоимость, meta-prompt оказался самым дорогим и хрупким способом. Прямой ответ и пошаговый способ стабильно решают 7/7 в обоих режимах.
