# День 8. Работа с токенами

Самостоятельный Spring Boot-сервис: агент с инструментами, сохранением контекста и подсчётом токенов на каждом вызове модели.

## Что считает агент

- **Запрос** — оценка токенов последнего сообщения пользователя;
- **Контекст** — фактические `prompt_tokens` из ответа API, то есть весь контекст, ушедший в модель;
- **Ответ** — фактические `completion_tokens`;
- **За сессию** — накопленная сумма prompt+completion по всем вызовам; это не размер контекста и может превышать контекстный лимит;
- **Стоимость вызова / Σ стоимость** — расчёт по тарифу DeepSeek Flash `$0.30 / $1.20` за 1M input/output;
- **Контекст** — фактический размер контекста и заполнение бюджета;
- **история по вызовам** — после каждого вызова в панели появляется строка `ctx / resp / Σ / $` с полосой заполнения контекста, поэтому видно, как токены и стоимость растут по мере диалога;
- шкала линейная; на фоне лимита 1 000 000 небольшие значения визуально почти не видны — это ожидаемо;
- при переключении гейта все уже накопленные точки и верхняя шкала перерисовываются относительно нового лимита.

Фактические значения берутся из `usage` ответа DeepSeek. Для следующего запроса guard учитывает `history + response + новое сообщение`: в контекст попадает не только прошлый prompt, но и ответ модели. Поэтому лимит проверяется до отправки, а не после того, как реальный контекст уже превышен.

## Переключатель гейта

В панели есть чекбокс **«Снять гейт сервиса»**.

- выключен (по умолчанию): работает локальный guard, в UI отображается `AGENT_CONTEXT_LIMIT`;
- включён: локальный guard отключается, в UI отображается **1 000 000** токенов — лимит модели.

При снятом гейте активируется кнопка **«Сказка про колобка (~1M токенов)»**. Она отправляет на сервер синтетический текст про Колобка примерно на миллион токенов; локальной остановки нет, поэтому запрос уходит к провайдеру, и уже API может вернуть ошибку контекста.

## Лимит

По умолчанию:

```text
app.agent.context-limit-tokens = 128000
```

Переопределяется переменной:

```bash
export AGENT_CONTEXT_LIMIT=2000
```

Если оценка контекста превышает лимит, агент:

1. не отправляет запрос в LLM;
2. присылает `llm_skipped` — карточку «запрос не отправлен» с причиной;
3. присылает `token_limit` для панели;
4. показывает ошибку в чате;
5. сохраняет историю как есть.

События `llm_request` и `llm_response` в этом случае отсутствуют: в API действительно ничего не ушло.

Это позволяет воспроизводимо показать переполнение, не набивая 128k токенов вручную. Для реального лимита конкретной модели значение задаётся конфигурацией.

## API и события

```text
GET  /api/agent/meta
GET  /api/agent/history?sessionId=...
POST /api/agent/chat     SSE: token_usage, token_limit, llm_skipped, llm_request, ...
POST /api/agent/reset
GET  /api/health
```

## Запуск

```bash
export DEEPSEEK_API_KEY="..."
mvn package
java -jar target/day08-token-budget-0.0.1-SNAPSHOT.jar
```

Для демонстрации переполнения:

```bash
AGENT_CONTEXT_LIMIT=2000 java -jar target/day08-token-budget-0.0.1-SNAPSHOT.jar
```

Снятие гейта и stress-сценарий доступны в UI; локальный guard при этом не работает, а лимит в панели меняется на `1 000 000`.

Живой stress-тест при снятом гейте:

```text
синтетическая сказка ≈ 1 081 588 токенов
лимит модели:        1 048 576
ответ DeepSeek:      HTTP 400 invalid_request_error
```

То есть локальный guard не сработал, запрос ушёл к провайдеру, и отказ вернул уже API.

UI: `http://localhost:8086/`.

## Проверка

Живой прогон с демо-лимитом `1800`:

### Короткий диалог

Запрос «Сколько будет 2+2?» (18 символов):

```text
currentRequest: 5
history:        596 → 668
response:       47 → 8
total:          643 → 1319
```

Агент сделал два вызова модели (обычный ответ и финальный), токены накапливались.

### Рост по диалогу

После каждого вызова в панели токенов появляется строка:

```text
#1  ctx 596  resp 47  Σ 643   $0.0002
#2  ctx 668  resp 8   Σ 1319  $0.0002
```

Полоса в строке показывает заполнение контекста, `Σ` и `$` — накопленные значения. Цена считается по `$0.30 / $1.20` за 1M input/output.

### Длинный диалог / переполнение

Добавлено сообщение на 8 482 символа:

```text
estimated context: 2280
limit:             1800
```

Агент **не отправил запрос в API**, вернул:

```text
token_limit: Контекст превышает лимит. Запрос к модели не отправлен.
```

То есть ограничение работает до сетевого вызова, а не после ошибки модели.

- токены tool calls и их результатов входят в `Контекст`;
- `За сессию` — накопленная стоимость сессии в токенах;
- заблокированный запрос добавляется в график отдельной красной точкой с пометкой «не отправлен»;
- счётчик `Отклонено` показывает запросы, по которым API не вернул `usage`; для них стоимость не начисляется и они помечаются в API-карточке;
- после `token_limit` история остаётся, можно начать новый чат.
