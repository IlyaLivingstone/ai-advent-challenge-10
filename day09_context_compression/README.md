# День 9. Сжатие истории

Самостоятельный Spring Boot-сервис: агент с инструментами, сохранением контекста и сжатием старых сообщений в отдельное summary.

## Механизм

- последние **8** сообщений отправляются в LLM как есть;
- более старые сообщения свёрнуты в `summary`;
- summary создаётся порциями по **10** сообщений;
- summary хранится отдельно в JSON-сессии и подставляется в запрос вместо полной истории;
- полная история при этом не удаляется и доступна в UI/истории;
- режим можно выключить переключателем **«Сжатие истории»** — тогда уходит вся история.

Summary экстрактивное: сохраняет предложения с деталями — именами, сроками, бюджетом, ограничениями, решениями. Поэтому конкретные факты не теряются при сжатии.

## Интерфейс

Три панели:

- слева — список сессий, создание и удаление;
- в центре — чат: reasoning, tool calls, API-трассы и настоящий потоковый ответ модели (DeepSeek `stream:true`);
- справа — эксперимент: сжатие, два сценария, summary и токены.

Обе боковые панели сворачиваются кнопками в тулбаре чата.

## Сценарные реплики

Сценарий не отправляет заранее заготовленные фразы. Для каждой следующей реплики сервер:

1. берёт последние сообщения диалога;
2. получает целевой ключевой факт;
3. отдельным внутренним запросом генерирует естественную реплику пользователя;
4. отправляет её агенту как обычное сообщение.

Генерация реплики:

- не попадает в историю чата;
- не добавляется в `TokenStats`;
- не отображается как API-шаг.

В чат попадают только сгенерированная пользовательская реплика и ответ агента. Контрольные вопросы после сценария остаются фиксированными.

## Проверка

Диалог из 10 фактов (имя, срок, бюджет, ограничение, решение, ответственный, аудитория, риск, формат, дата старта):

- после накопления сообщений сработало сжатие: `summarizedCount = 10`;
- в summary попали ключевые детали;
- после сжатия вопрос «Напомни имя проекта, срок, бюджет и ограничение»;

ответ:

```text
Колобок — срок: 15 декабря,
бюджет: 300 000 ₽,
ограничение: запрет на использование внешних API.
```

То есть детали сохранились через summary, а в запрос ушла не вся история, а summary + последние 8 сообщений.
