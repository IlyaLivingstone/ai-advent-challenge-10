# День 13. Состояние задачи (Task State Machine)

Spring Boot-сервис поверх Дня 12: память, профили, сессии и ветвление сохранены,
а поведение агента ограничено кодовым конечным автоматом этапов задачи.

Сервис: `http://localhost:8091/`. Модуль независим от Дня 12 и запускается на своём порту.

## Этапы и переходы

Формальные этапы задачи:

```text
planning → execution → validation → done, с возвратом validation → execution при провале проверки
```

Разрешены только эти переходы. Автомат проверяет их кодом **до** изменения состояния:
запрещённый переход возвращает `409 Conflict` с понятным сообщением, а сессия и файл сессии
остаются нетронутыми.

На любом активном этапе (`planning`, `execution`, `validation`) доступны:

- пауза — `POST /api/agent/task/pause`;
- продолжение — `POST /api/agent/task/resume`.

Этап `done` терминальный: пауза и переходы из него отклоняются. Пока задача на паузе,
смена этапа запрещена — сначала нужно продолжить выполнение.

Состояние хранится в сессии (`SessionSnapshot.taskState`) и переживает перезапуск:

- `stage` — текущий этап;
- `currentStep` — текущий шаг (по умолчанию берётся из этапа);
- `expectedAction` — ожидаемое от агента действие;
- `paused` — признак паузы;
- `updatedAt` — время изменения.

Журнал изменений (`transition`, `pause`, `resume`) хранится в `SessionSnapshot.taskHistory`.

## API

```text
GET  /api/agent/task/state?sessionId=...   # состояние + разрешённые переходы + журнал
GET  /api/agent/task/transitions           # описание автомата: этапы и переходы
POST /api/agent/task/transition            # {"sessionId": "...", "stage": "execution", "currentStep": "..."}
POST /api/agent/task/pause                 # {"sessionId": "..."}
POST /api/agent/task/resume                # {"sessionId": "..."}
```

Пример запрещённого перехода:

```text
POST /api/agent/task/transition
{"sessionId": "...", "stage": "validation"}

409 Conflict
{
  "error": "Недопустимый переход состояния задачи: planning → validation. ... Состояние не изменено.",
  "action": "transition",
  "from": "planning",
  "to": "validation",
  "allowedTransitions": ["execution"],
  "stateChanged": false
}
```

## UI

В верхней панели три кнопки: «Память», «Профиль», «Задача». Панель «Задача» показывает
этап, текущий шаг, ожидаемое действие, разрешённые переходы, признак паузы и журнал
изменений. Кнопки недопустимых переходов неактивны, а серверная проверка остаётся
обязательной для любого запроса: прямой вызов API или сценарий получает `409`.

Сценарий «Сценарий состояния задачи» создаёт новую сессию и проверяет:

1. старт с `planning`;
2. запрещённый переход `planning → validation` — `409`, состояние не изменилось;
3. прямую просьбу ассистенту нарушить порядок — этап остаётся `planning`;
4. разрешённый переход `planning → execution`;
5. запрещённый переход `execution → done` — `409`;
6. паузу: переходы заблокированы, текущий шаг сохранён;
7. ответ ассистента на паузе без выполнения действий;
8. продолжение без повторных объяснений и без потери шага;
9. `execution → validation → done`, при провале `validation → execution`;
10. `409` на паузу в терминальном `done`.

Панели памяти и профиля работают и тогда, когда открыта панель «Задача»: данные
берутся из сессии и попадают в промпт независимо от видимости панели. Заметки UI
в историю и контекст модели не пишутся — в истории остаются только роли
`system`, `user`, `assistant` и `tool`.

## Промпт

Состояние задачи добавляется в каждый запрос отдельным system-блоком вместе с профилем
и слоями памяти, не изменяя их:

```text
Состояние задачи (конечный автомат):
- этап: execution — Выполнение
- текущий шаг: ...
- ожидаемое действие: ...
- пауза: нет
- следующий разрешённый этап: validation
Не меняй этап самостоятельно ... переходы состояний выполняет только код.
```

## Память и профили (из Дня 12)

- слои памяти: краткосрочная, рабочая, долговременная; правила слоёв и авто-раскладка;
- профили: выбор, создание, редактирование и автообновление из диалога;
- сессии: список, создание, удаление, ветвление (ветка копирует состояние задачи);
- токены, сжатие контекста и выбор стратегии.

## Проверка сценария через API

```bash
SESSION=$(curl -s -X POST http://localhost:8091/api/agent/sessions | jq -r .sessionId)

# planning, разрешён только execution
curl -s "http://localhost:8091/api/agent/task/state?sessionId=$SESSION"

# запрещено: 409 и stateChanged=false, состояние остаётся planning
curl -s -X POST http://localhost:8091/api/agent/task/transition \
  -H 'Content-Type: application/json' \
  -d "{\"sessionId\":\"$SESSION\",\"stage\":\"validation\"}"

# разрешено: planning → execution с текущим шагом
curl -s -X POST http://localhost:8091/api/agent/task/transition \
  -H 'Content-Type: application/json' \
  -d "{\"sessionId\":\"$SESSION\",\"stage\":\"execution\",\"currentStep\":\"Шаг 1\"}"

# пауза, затем переход на паузе должен вернуть 409, продолжение — 200
curl -s -X POST http://localhost:8091/api/agent/task/pause \
  -H 'Content-Type: application/json' -d "{\"sessionId\":\"$SESSION\"}"
curl -s -X POST http://localhost:8091/api/agent/task/resume \
  -H 'Content-Type: application/json' -d "{\"sessionId\":\"$SESSION\"}"
```

Дальше: `execution → validation → done`; при провале проверки `validation → execution`. Из `done` переходы и пауза возвращают `409`.
Неизвестный этап (например, `review`) возвращает `400`. После перезапуска сервиса
`GET /api/agent/task/state` возвращает сохранённые этап, шаг, паузу и журнал.

## Ограничения

- Этап меняет только код через API; ассистент не может сделать это самостоятельно и
  получает в промпте явный запрет.
- `done` терминален: вернуть задачу в работу можно только через `reset` или новую сессию.
- Пауза блокирует смену этапа; чат при этом доступен, но промпт требует не выполнять
  новых действий до `resume`.
- Живой сценарий с ответами ассистента требует `DEEPSEEK_API_KEY`; проверки автомата
  через API работают и без ключа.
- Состояние задачи хранится в файле сессии (`data/sessions` по умолчанию) и относится
  к конкретной сессии; ветвление копирует снимок состояния на момент создания ветки.
